# Environment variables

Names only. Values stay in Coolify, GitHub Actions secrets, or the server environment. Never commit them and never put `REDIS_URL` behind `NEXT_PUBLIC_`.

Each name has one primary class: `PUBLIC BUILD`, `SERVER RUNTIME`, `WORKER`, `SOCIAL`, `WEBHOOK`, `DATABASE`, `OPTIONAL`, or `DEPRECATED`. A process may still need a name from another class when it performs that work. Build-time means the Next client bundle inlines the value during `next build`. Runtime means the server or worker reads it when the process starts.

## Classified inventory

### PUBLIC BUILD

`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_UPMIND_ORDER_CONFIG_URL`, `NEXT_PUBLIC_UPMIND_WIDGET_SCRIPT_URL`, `NEXT_PUBLIC_UPMIND_DAC_SCRIPT_URL`, `NEXT_PUBLIC_UPMIND_BRAND_ID`, `NEXT_PUBLIC_UPMIND_ACCOUNT_ID`, `NEXT_PUBLIC_UPMIND_CURRENCY`, `NEXT_PUBLIC_UPMIND_DOMAIN_SEARCH_MODE`, `NEXT_PUBLIC_LIVE_CHAT_PROVIDER`, `NEXT_PUBLIC_TIDIO_PUBLIC_KEY`, `NEXT_PUBLIC_CRISP_WEBSITE_ID`, `NEXT_PUBLIC_INTERCOM_APP_ID`, `NEXT_PUBLIC_HUBSPOT_PORTAL_ID`.

The first three are required for a usable bundle. The rest are optional public values and may be empty until that feature is on. `VITE_LIVE_CHAT_PROVIDER`, `VITE_TIDIO_PUBLIC_KEY`, `VITE_CRISP_WEBSITE_ID`, `VITE_INTERCOM_APP_ID`, and `VITE_HUBSPOT_PORTAL_ID` are read only as fallbacks for the matching `NEXT_PUBLIC_` names.

### DATABASE

`DATABASE_URL`, `DIRECT_URL`. Supabase only. `DIRECT_URL` is for migrations. `PGSSL_REJECT_UNAUTHORIZED` is `SERVER RUNTIME` on Coolify and must be `true` unless a CA problem is documented. `PRISMA_POOL_MAX` is `OPTIONAL`.

### SERVER RUNTIME

`NODE_ENV`, `PORT`, `HOST`, `TAKATAK_PROCESS`, `SUPABASE_SECRET_KEY` or `SUPABASE_SERVICE_ROLE_KEY`, `EMAIL_USER`, `EMAIL_PASSWORD`, `SENDER_EMAIL`, `SMTP_HOST`, `SMTP_PORT`, `GMAIL_APP_PASSWORD`, `OTP_EMAIL_ADAPTER`, `CRON_SECRET`, `TAKATAK_READY_REQUIRE_DATABASE`, `HEALTH_DETAILS_ENABLED`.

`TAKATAK_FOUNDATION_MODE_ENABLED` and `ALLOW_FOUNDATION_SEED` stay unset in production. `OTP_MEMORY_PATH` is test-only.

### WORKER

`REDIS_URL`, `REDIS_PASSWORD` (Redis container only), `TAKATAK_QUEUE_PREFIX`, `TAKATAK_QUEUE_ENABLED`, `TAKATAK_QUEUE_WEBHOOKS`, `TAKATAK_PROCESS` (`general`, `social`, or `webhooks`), `SOCIAL_SYNC_WORKER_LIMIT`, `HOCKEY_DELIVERY_WORKER_ENABLED`, `HOCKEY_DELIVERY_WORKER_SECRET`.

The web process needs `REDIS_URL` and the queue flags only when it enqueues. Workers do not get a public domain.

## Build-time (`NEXT_PUBLIC_*`)

Required for a usable browser bundle:

| Name | Why |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase client |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon key. Public by design, still not committed |
| `NEXT_PUBLIC_APP_URL` | Absolute app origin. Not derived from the request Host header |

Read by the client bundle when those features are used. Empty is valid until the feature is turned on:

| Name | Source |
| --- | --- |
| `NEXT_PUBLIC_UPMIND_ORDER_CONFIG_URL` | `src/lib/website/upmind-config.ts` |
| `NEXT_PUBLIC_UPMIND_WIDGET_SCRIPT_URL` | same |
| `NEXT_PUBLIC_UPMIND_DAC_SCRIPT_URL` | same |
| `NEXT_PUBLIC_UPMIND_BRAND_ID` | same, also server fallback |
| `NEXT_PUBLIC_UPMIND_ACCOUNT_ID` | same |
| `NEXT_PUBLIC_UPMIND_CURRENCY` | same |
| `NEXT_PUBLIC_UPMIND_DOMAIN_SEARCH_MODE` | same |
| `NEXT_PUBLIC_LIVE_CHAT_PROVIDER` | `live-chat-config.ts` maps `VITE_LIVE_CHAT_PROVIDER` |
| `NEXT_PUBLIC_TIDIO_PUBLIC_KEY` | maps `VITE_TIDIO_PUBLIC_KEY` |
| `NEXT_PUBLIC_CRISP_WEBSITE_ID` | maps `VITE_CRISP_WEBSITE_ID` |
| `NEXT_PUBLIC_INTERCOM_APP_ID` | maps `VITE_INTERCOM_APP_ID` |
| `NEXT_PUBLIC_HUBSPOT_PORTAL_ID` | maps `VITE_HUBSPOT_PORTAL_ID` |

`NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` and `NEXT_PUBLIC_APP_NAME` appear in old docs or mock copy. Application code does not read them from `process.env`.

The root `Dockerfile` declares the names above as `ARG`/`ENV` and fails the build if the three required ones are empty. Coolify build arguments vs runtime: set public values in the build args. Set secrets only in the runtime environment. A runtime change to `NEXT_PUBLIC_*` does not change an already built bundle.

## Web runtime

Required for a real deployment (`src/lib/ops/env-preflight.ts` and `server.js`):

| Name | Notes |
| --- | --- |
| `NODE_ENV` | `production` |
| `PORT` | Coolify injects this. `next start` binds `0.0.0.0` |
| `HOST` | `0.0.0.0` |

| `DIRECT_URL` | Supabase direct, migrations only |
| `NEXT_PUBLIC_SUPABASE_URL` | Also required at build |

| `NEXT_PUBLIC_APP_URL` | Also required at build |
| `SUPABASE_SECRET_KEY` or `SUPABASE_SERVICE_ROLE_KEY` | Server only |
| `EMAIL_USER` + `EMAIL_PASSWORD`, or `SENDGRID_API_KEY` | OTP mail. Mailboxes stay on MochaHost |

Coolify-only:

| Name | Default | Notes |
| --- | --- | --- |
| `TAKATAK_READY_REQUIRE_DATABASE` | unset / false | `true` makes `/api/health/ready` fail when the database is not `ok` |
| `REDIS_URL` | unset | If set, readiness pings Redis. Unset stays `not_configured` and does not fail |
| `TAKATAK_QUEUE_ENABLED` | false | Social Redis signals |
| `TAKATAK_QUEUE_WEBHOOKS` | false | Stripe deferral. Keep false until the webhooks worker is running |

`PGSSL_REJECT_UNAUTHORIZED` and `PRISMA_POOL_MAX` exist for the Passenger host. Do not copy `server.js`'s forced `sslmode=no-verify` into Coolify. Supabase wants normal TLS. Set `PGSSL_REJECT_UNAUTHORIZED=true` on Coolify unless a documented CA issue appears.

## Least privilege by process

| Process | Needs | Must not need |
| --- | --- | --- |
| Web | Supabase, database, the feature secrets for routes it serves, `CRON_SECRET` if it still exposes the cron route | Redis write access can be omitted while queue flags are false |
| General worker | none today. No Redis connection | Provider secrets |
| Social worker | `REDIS_URL`, `DATABASE_URL`, Supabase admin, `SOCIAL_TOKEN_ENCRYPTION_KEY_V1`, Meta app secret | Stripe webhook secret, Twilio verify, Coolify token |
| Webhooks worker | `REDIS_URL`, `DATABASE_URL`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` is not required to re-fetch an event, price id env, Supabase admin | Meta app secret, social encryption key, unless a future handler needs them |
| Redis | password via `requirepass`, no Coolify public port | Application secrets other than its own password |

`REDIS_URL` for an app user should be a dedicated password. Staging and production Redis are different URLs and should use different `TAKATAK_QUEUE_PREFIX` values (`takatak-staging`, `takatak-prod`).

GitHub Actions secrets used by this repo, not application env: `PRODUCTION_SUPABASE_ANON_KEY` (CI production build), `TAKATAK_PRODUCTION_DATABASE_URL` (migration reconcile workflow only). Coolify deploy, when configured later: `COOLIFY_DEPLOY_WEBHOOK_URL`, `COOLIFY_DEPLOY_WEBHOOK_TOKEN`. The workflow does not contain a URL.

## Encryption keys

Do not rotate `SOCIAL_TOKEN_ENCRYPTION_KEY_V1`, `HOCKEY_TOKEN_ENCRYPTION_KEY_V1`, or `HOCKEY_TRAVEL_ENCRYPTION_KEY_V1` as part of the hosting move. Copy the existing values into Coolify. Regenerating them makes stored tokens unreadable.
